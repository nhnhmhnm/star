# 향후 구현 계획서

이번 작업은 기획 문서까지만 진행한다. 아래 개발·설치·실행·배포 단계는 향후 계획이며 현재 수행하지 않는다.

## Phase 0 — 핵심 의존성 검증

- Stellarium 고정 커밋·빌드 도구·JS/WASM 공급 방식
- 별·서양 sky culture·폰트의 확보와 별도 준비 상태
- 클릭 위치·현재 UTC·MJD·각도 단위, 지평선 시선 고정
- 대기 켜짐 상태에서 태양·달에 따른 배경 밝기와 별 표시
- 밤 조건 -18° 이하 판정, 로딩 완료·복귀·관측 중 차단
- 엔진 내부 시간 진행 해제와 앱의 현재 UTC 전달
- 시선 이동·FOV 20~120°·선/이름 토글·모바일 제스처
- 리소스 해제 또는 단일 엔진 운영, 반복 진입 성능
- 기상 후보 API의 계약·유효 시각·운량·이용 조건 검토
- 구름 합성은 별도 작은 검증으로 시선·줌·가림·모바일 성능 확인

종료 조건은 현재 밤 위치의 하늘과 별자리를 재현 가능한 버전으로 표시하고 주요 입력·차단 정책을 확인하는 것이다. 기상 요약과 구름 화면 합성은 별도 결과로 기록한다. hover는 필수 종료 조건이 아니다.

## Phase 1 — 앱과 관측 상태

화면·라우트·어댑터·확정 위치·현재 시계·밤 판정·오류 경계를 구성한다. 시간 조작 모드나 직접 좌표 입력 화면은 만들지 않는다. 위치가 없는 하늘 경로는 지도로 보낸다.

## Phase 2 — 현재 밤하늘

현재 UTC 동기화, 초기 시선과 줌, 별자리 선·이름, 대기·지평선 표시, 로딩·부분 실패, 탭 복귀를 연결한다. 관측 중 -18° 기준을 벗어나면 하늘을 가리고 종료 안내를 제공한다.

## Phase 3 — 세계지도와 검색

- 지도/검색 제공자와 비용 확정, 일반 도로·지명 지도
- 드래그·스와이프·휠·핀치·줌 버튼
- 도시·장소 검색 → 지도 이동·확대 → 최종 지도 클릭 좌표 확정
- 검색 변경 시 이전 선택 해제, 지도 제스처와 선택 클릭 구분
- 낮 중심부가 밝고 밤으로 갈수록 어두워지는 현재 태양 기반 그라데이션
- h <= -18° 관측 가능 영역은 같은 밤 색상·투명도로 고정, 지명·도로 가독성을 위한 음영 상한 적용
- 장식 밝기와 별도로 -18° 관측 가능 경계·범례 표시
- 날짜변경선·세계지도 반복·검색/타일 실패·키보드 대체 선택
- 클릭·진입·로딩 완료의 현재 밤 조건 재검증

## Phase 4 — 기상 반영 채택 범위 구현

기상 요약부터 연결하고, Phase 0 결과가 충분하면 운량 기반 구름 합성을 추가한다. 선택 좌표·응답 순서·15분 갱신 제안·유효 시각·지연/미반영 정책을 함께 구현한다. 맑음 고정이나 항상 소량의 장식 구름으로 대체하지 않는다.

## Phase 5 — 품질과 출시 준비

[검증 계획](./test-plan.md)의 요구사항을 실제 기기에서 확인한다. 지도 가독성, 현재 시각 유지, 밤 차단, 대기 배경 변화, 구름 성능·실패, 리소스 누수, 배포 경로·MIME·CORS와 자산 이용 조건을 기록한다. 출시 준비가 끝난 뒤 배포 단계를 진행한다.

## 후속 확장

- 별자리 한글 이름·상세 설명·선택 UX
- 현재 위치로 지도 이동 후 최종 클릭
- 지도 위치 공유 후 현재 밤 재판정
- 같은 현재 시각의 두 밤 지역 비교
- 지형·광공해·고도별 기상 표현

배속·정지·과거/미래 시각·다음 밤으로 이동은 후속 목록에도 넣지 않는다. 기획 완료와 실행 검증·개발 완료를 구분한다.
