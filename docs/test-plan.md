## 2. 계산 경계

- 기본 설정에서 태양 고도 -18.001° 허용, -18° 허용, -17.999° 차단
- 환경 변수를 -12로 바꾼 경우 -12° 허용·-11.999° 차단, 지도 음영·카드·진입·종료가 같은 경계 사용
- 숫자 아님, -90 미만, 0 초과 설정에서 서버 시작 실패; 설정 API 실패 시 관측 진입 차단
- 0°·-6°·-12° 단계 구분, 날씨 is_day와 진입 정책 혼용 없음
- SunCalc 1.9.0 rad → deg, 버전 교체 시 기하/겉보기 고도 재검증
- 날짜변경선·반복 지도 경도, lat/lng 순서, NaN·Infinity 거부
- 지도 선택 가능 고위도에서 극야·백야와 밤이 없는 계절
- UTC 1970-01-01T00:00:00Z → MJD 40587, 하루 → +1, 180° → π rad
- 동일 시각 스냅샷으로 지도 밝기·관측 가능 경계·카드 계산
- 화면 색을 샘플링하거나 기기 현지 시각으로 관측 가능 여부 판정하지 않음

## 3. 지도 E2E

첫 진입에서 유효하지 않은 닉네임은 지도를 열지 못한다. 유효한 닉네임은 같은 탭 새로고침에 유지되고 새 탭에는 자동 복사되지 않는다. 중복 닉네임의 서로 다른 내부 participantId를 구분한다. 닉네임을 HTML로 해석하지 않는다.

검색 → 결과 선택 → 이동·확대 완료 → 아직 진입 불가 → 지도 클릭 → 클릭 좌표 표시 → 밤 조건 충족 시 진입한다. 검색 중심과 클릭 좌표가 다른 사례로 확인한다.

검색 결과 재선택은 이전 관측 위치를 해제한다. 스와이프 종료·핀치·더블클릭 줌·검색 목록 클릭은 관측 위치로 확정되지 않는다. 지도만 움직였을 때 기존 좌표를 임의 변경하지 않는다.

검색 실패는 수동 지도 탐색, 지도 실패는 새 선택 차단·재시도다. 입력 좌표로 우회하는 경로는 없다. 키보드 중심 이동 후 명시적 선택이 같은 검증 함수를 거친다.

두 브라우저에서 서로 다른 밤하늘을 열어 각 관측 위치의 근사 핀이 상대 지도에 나타나는지 확인한다. 같은 0.25° 셀의 사용자는 한 집계 핀과 정확한 인원수로 보이며 상세에 닉네임이 표시된다. 정확한 클릭 좌표와 셀 중심이 다른 사례로 API·화면 어디에도 원본 좌표가 공개되지 않는지 확인한다.

## 4. 실시간·차단 E2E

- 낮·모든 박명 위치 클릭 → 이유 안내, 진입 차단
- 밤 위치 클릭 후 로딩 중 -18° 초과 → 첫 하늘 표시 전 차단
- 감상 중 기준 초과 → 다음 매초 판정에서 하늘 가림·중단
- 탭을 비운 동안 아침이 됨 → 복귀 첫 화면은 종료 안내
- 시스템 시계 변경 → 현재 UTC·밤 조건 다시 반영
- 오래된 링크의 date/utc/speed 매개변수 → 현재 시각만 사용
- 흐린 밤은 진입 가능, 기상 실패도 밤 판정을 우회하지 않음
- 지도 복귀·밤 조건 종료 → presence remove, 강제 연결 종료 → 60초 안에 TTL 제거
- WebSocket 재연결 중 오래된 핀 제거와 상태 안내, presence 장애 중 지도·하늘 핵심 기능 유지

별의 자연스러운 이동은 고정 시선·추적 해제 상태에서 실제 5~10분 경과 전후를 비교한다. 정밀 계산 테스트에는 고정 UTC를 주입할 수 있으나 제품에 배속이나 시간 이동을 만들지 않는다. 테스트 fake clock이 WASM 루프까지 검증했다고 간주하지 않는다.

## 5. 메인 지도 밝기

- 한국의 낮 정오 부근: 한국을 포함한 낮 영역이 넓고 밝게 보이고 주변에서 부드럽게 감쇠
- 밝은 중심이 검색 위치나 마우스가 아니라 현재 태양 위치를 따라감
- 계절·위도와 평면 투영을 고려하며 지도 화면의 고정 원형 그라데이션에 머물지 않음
- 밝은 아침 지역·박명·밤이 시각적으로 구분됨
- h=-18°·-30°·-60° 지점의 밤 상태 레이어 색·투명도가 동일함
- 같은 관측 가능 영역에서는 달·운량이 달라도 지도 상태색이 달라지지 않음
- 동일 밤 음영에서도 작은 지명·도로·선택 마커가 읽히고 클릭 가능
- 단일·집계 관측자 핀이 밤 음영 위에서 읽히고 선택 마커와 혼동되지 않음
- 날짜변경선·반복 지도에서도 음영 이음새와 경계 단절 없음
- 지도 pan/zoom 후 음영이 지리 위치에 붙어 있음
- 밝기 음영과 -18° 관측 가능 여부의 차이를 범례·카드로 이해 가능

## 6. 하늘 배경·기상

소스 확인과 실제 브라우저 표현을 구분한다. 개발용 고정 시간으로 대기 켜짐 시 낮·박명·밤 배경을 비교하되 제품의 낮 진입 차단을 해제하는 기능을 배포하지 않는다. 실제 제품은 설정된 기준 이하만 표시하며 기본값은 -18°다.

밤 내부에서도 달 위치·밝기에 따른 배경 차이, 지평선 방향, FOV를 확인한다. 도시 광공해가 실제 좌표에 자동 연동됐다고 가정하지 않는다. 흐린 하늘을 반드시 검정에 가까워지는 것으로 검증하지 않는다.

기상 채택 시 운량 0/부분/100의 경향, 구름 뒤 별·별자리 가림, 시선·줌 일관성, 동작 줄이기, 누락 운량·오래된 시각·순서가 뒤바뀐 응답을 확인한다. 데이터 기준 시각과 조회 시각을 구분하고 운량 비율을 광학 두께로 오인하지 않는다.

## 7. 기준 위치·성능

서울(37.5665,126.9780), 시드니(-33.8688,151.2093), 뉴욕(40.7128,-74.0060), 런던(51.5074,-0.1278), 날짜변경선 부근을 사용한다. 같은 UTC에 모두 밤일 필요는 없다. 위치마다 해당 시각의 허용/차단을 함께 검증한다.

성능 제안 조건: 10Mbps·RTT 100ms·캐시 비움·5회 반복. 지도 UI 3초, 하늘 필수 데이터 10초, 데스크톱 60fps·모바일 30fps는 미측정 목표다. 실제 기종/OS/브라우저와 최초 타일·WASM 컴파일·기상 준비 시간을 따로 기록한다.

실시간 감상 10분, 지도/하늘 왕복 10회, 구름 합성 유무에 따른 메모리·프레임·WebGL context·listener 누수를 확인한다.

## 9. Python API 검증

FastAPI TestClient와 pytest로 공개 설정의 기본값·범위·잘못된 환경 변수, 닉네임 문자·길이·메시지 크기, presence 등록·heartbeat·종료·TTL 만료·호출 제한을 확인한다. 이후 기상 도입 시 정상 좌표·범위 오류·외부 시간 초과·잘못된 응답·캐시 만료와 기상 유효 시각을 검증한다. 외부 서비스는 모의 응답으로 검증하고 실제 네트워크 확인은 별도 기록한다.

FastAPI에서 내보낸 OpenAPI와 웹 요청/응답 타입의 계약 불일치를 확인한다. API 린트·포맷은 Ruff, 테스트는 pytest로 수행하고 착수 시 정한 Python 타입 검사도 적용한다. 실제 선택 위치나 비밀 키를 테스트 로그에 노출하지 않는다. 해당 기능 커밋에 필요한 검증을 포함한다. [FastAPI 테스트 문서](https://fastapi.tiangolo.com/tutorial/testing/)

## 10. 책임 경계 검증

- 밤 정책·좌표 변환은 시간·입력을 전달한 순수 함수로 검증한다.
- presence 격자 변환은 경계·음수·날짜변경선을 확인하고 PresenceService는 fake 저장소·고정 서버 시계로 TTL과 이벤트를 검증한다.
- WeatherService는 fake 제공자·고정 시계로 정상·지연·누락·공급자 오류를 확인한다.
- 실제 제공자 어댑터는 대표 외부 응답을 앱 계약으로 변환하는지 검증한다. fake 테스트만으로 실제 API 계약을 검증했다고 보지 않는다.
- 동시에 서로 다른 좌표를 조회할 때 공유 서비스의 상태가 요청 사이에 섞이지 않는지 확인한다.
- 지도·하늘 어댑터는 반복 초기화·이탈·해제에서 리소스 소유권과 기존 수명주기 규칙을 지키는지 확인한다.
- WebSocket 클라이언트는 Strict Mode·재연결·탭 숨김·라우트 왕복에서 연결과 heartbeat가 중복되지 않는지 확인한다.

클래스의 private 메서드 호출 순서를 복제하는 테스트 대신 사용자가 보는 결과·계약·자원 정리를 검증한다. [객체지향 설계](./object-oriented-design.md)
