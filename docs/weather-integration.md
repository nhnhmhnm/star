# 기상 반영 검토안

이 문서는 공식 자료로 확인한 데이터 공급 가능성과 제안하는 표현 범위의 기준이다. 엔진 연동이나 구름 렌더링 검증 결과는 별도 커밋과 문서에 남긴다.

## 1. 가능한 경험

선택한 위치의 최신 기상 데이터를 받아 운량에 따라 구름의 분포와 별이 가려지는 정도를 바꿀 수 있다. 맑음·흐림·비·눈 등의 상태와 데이터 기준 시각도 함께 표시한다.

Open-Meteo는 위도·경도 기반 현재 기상 요청에서 운량, 날씨 코드, 강수, 풍속 등의 값을 제공한다. 현재값은 기상 모델 기반이며 현장의 초단위 센서 실황과 같지 않다. 문서의 15분 시간 간격을 새 관측이나 모델의 15분 갱신 보장으로 해석하지 않는다. [공식 API 문서](https://open-meteo.com/en/docs)

## 2. 권장 범위

| 단계 | 기획안 | 상태 |
|---|---|---|
| 기상 요약 | 맑음/흐림/강수, 운량, 데이터 기준 시각 | 우선 도입 제안 |
| 기본 구름 | 운량 기반의 느린 구름과 가림 효과 | 엔진 합성·모바일 성능 검증 후 채택 |
| 비·눈·안개 | 우선 상태 안내, 입자·안개 효과는 후속 | 확장안 |
| 실제 구름 형상 | 현장 카메라·위성 등 추가 정보와 별도 복원 필요 | 현재 범위 제외 |

항상 약간의 구름을 넣는 장식은 실제 날씨와 어긋날 수 있다. 맑으면 구름이 거의 없고 흐리면 더 많이 가리는 방향을 제안한다. 흐린 밤에도 진입은 가능하지만 별이 적게 보일 수 있다. 기상 상태는 밤 진입 조건과 분리한다.

## 3. 엔진과의 연결

공식 자료에서 확인한 Stellarium의 대기 표현만으로 실제 기상 API 연동과 구름 시각화가 자동 제공된다고 판단하지 않는다. 이번에 확인한 README와 대기 모듈에서는 그러한 통합 기능을 확인하지 못했다. 따라서 기상 조회와 구름 표현은 앱이 추가하는 기능으로 계획한다. [엔진 기능](https://github.com/Stellarium/stellarium-web-engine), [대기 모듈](https://github.com/Stellarium/stellarium-web-engine/blob/master/src/modules/atmosphere.c)

제안 구조는 `현재 좌표 → 기상 제공자 → 데이터 정규화 → 기상 안내·구름 표현`이다. 엔진은 현재 시각의 별 배치에 집중한다.

- 운량은 하늘을 덮는 비율이지 구름의 불투명도가 아니다. 전체 화면에 동일한 어둠을 더하는 단순 대응을 피한다.
- 구름의 형태·광학 두께·고도별 분포는 기본 API 값만으로 결정되지 않는다. 표현용 추정값과 실제 데이터를 구분한다.
- 구름은 지평선 기준 방향에 연결하고 시선 이동·줌과 일관되게 투영한다. 화면에 붙은 그림처럼 따라다니는지 검증한다.
- 별과 별자리 선·이름을 같은 가림 규칙으로 처리해 구름 뒤의 선만 떠 보이지 않게 한다. 조작 UI는 가리지 않는다.
- 첫 검증은 가벼운 합성 레이어로 진행하되 지원 훅·정렬·WebGL context 수·기기 성능을 확인한다. 엔진 자체에 해당 기능이 있다고 가정하지 않는다.
- 지상 10m 풍향·풍속을 구름의 실제 이동 방향·속도로 그대로 사용하지 않는다. 초기 구름 움직임은 느린 표현용 애니메이션이며 관측된 궤적이 아니다.
- 사용자의 동작 줄이기 설정에서는 구름 이동을 줄이거나 멈춰도 천문 시각은 계속 현재를 따른다.

## 4. 갱신·실패 정책 제안

관측 위치가 클릭으로 확정되고 밤 진입 조건을 통과한 뒤 조회한다. 검색 입력·지도 이동·매 프레임에는 기상을 요청하지 않는다.

- 활성 뷰어에서 15분마다 갱신을 시도하고 제공자의 제한에 맞춰 조정한다.
- 탭 복귀·재진입 시 캐시의 좌표와 기준 시각을 확인한다.
- 위치를 바꾸면 이전 요청을 취소하거나 응답을 무시한다. 요청 ID와 정규화된 좌표 키가 모두 현재 선택과 맞아야 한다.
- API가 반환한 격자 좌표를 클릭한 관측 좌표로 덮어쓰지 않는다.
- 데이터 유효 시각과 가져온 시각을 별도 저장한다. 모델 실행 시각이 있으면 별도 기록하고, 조회 시각을 관측 시각이라고 부르지 않는다.
- 초기 신선도 정책: 현재 UTC보다 30분 넘게 오래된 데이터는 지연 표시, 60분 넘으면 효과 적용 중단. 제공자 특성 확인 후 조정할 기획값이다.
- 누락·범위 오류·예상 밖 미래 시각·요청 실패를 맑음이나 운량 0으로 치환하지 않는다.
- 첫 조회 실패 또는 오래된 데이터는 `기상 미반영`을 명시하고 기본 천문 하늘을 제공한다. 기존 값이 유효하면 지연 안내와 함께 유지한다.
- 새 데이터는 짧은 전환으로 연결해 구름이 갑자기 바뀌지 않게 한다. 이는 시각적 보간이며 더 잦은 기상 관측을 뜻하지 않는다.

## 5. 사용자에게 보이는 정보

예: `구름 많음 · 운량 70% · 기상 기준 21:15 · Open-Meteo`

도움말: `구름은 기상 데이터를 바탕으로 표현하며 실제 구름 모양과 다를 수 있습니다.`

데이터 지연 시 `기상 정보 갱신 지연`, 적용할 수 없으면 `기상 미반영`을 표시한다. 별은 현재 시각에 따라 움직이고 기상은 주기적으로 갱신된다는 차이를 짧게 설명한다.

## 6. 공급자·비용

Open-Meteo를 초기 검토 후보로 둔다. 무료 API는 비상업 이용 조건·호출 제한·가용성 조건이 있고 상업용 제공 방식은 별도다. 데이터 귀속 표시도 필요하다. 운영 형태와 예산을 정하기 전에 무료 영구 운영으로 확정하지 않는다. [공식 요금·이용 안내](https://open-meteo.com/en/pricing)

향후 유료 키 은닉이나 전체 트래픽 제한이 필요하면 작은 서버 프록시를 검토한다. 프런트엔드 번들에 비밀 키를 넣지 않는다. 현재 단계에서는 가입·결제·실제 위치 전송·API 호출 실험을 하지 않는다.

## 7. 검증 후 결정할 것

구름 표현까지 첫 버전에 포함할지는 시선·줌 일관성, 운량별 가림 품질, 별자리 가림, 모바일 프레임, 기상 실패 안내가 확인된 뒤 결정한다. 기상 요약은 먼저 제공할 수 있으며 화면 합성의 성공 여부와 분리한다.
