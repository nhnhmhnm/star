# 닉네임·실시간 관측자 핀 기획

기준일: 2026-09-09. 이 문서는 회원가입 없이 시작하는 방문 세션과 메인 세계지도의 실시간 관측자 핀을 정의한다. 채팅과 소셜 로그인은 후속 범위로 분리한다.

## 1. 기능의 목적과 용어

페이지에 들어온 사용자는 먼저 닉네임을 정한다. 이후 밤하늘 화면을 실제로 보고 있는 사용자의 **관측 위치**를 메인 세계지도에서 확인할 수 있다. 관측 위치는 사용자가 지도에서 선택한 장소이며 기기의 GPS나 실제 거주 위치를 뜻하지 않는다.

핀은 “지금 다른 사람도 이 지역의 하늘을 보고 있다”는 감각을 주기 위한 실시간 상태다. 로그인 사용자 수, 누적 방문자 수, 해당 지역의 인구를 의미하지 않는다.

## 2. 닉네임 방문 세션

- 첫 진입 시 지도보다 먼저 닉네임 입력 화면을 표시한다.
- 앞뒤 공백을 제거한 2~20자의 한글·영문·숫자·공백·밑줄·하이픈을 허용한다. 제어 문자와 HTML은 허용하지 않고 서버에서도 같은 규칙으로 다시 검증한다.
- 닉네임은 중복을 허용한다. 로그인 전에는 소유권이나 본인임을 보장하지 않으며 프로필·친구·검색 기능을 제공하지 않는다.
- 브라우저 탭의 `sessionStorage`에 닉네임과 클라이언트 세션 식별자를 보관한다. 새로고침에는 유지되고 탭을 닫으면 사라진다.
- 서버가 발급한 임시 세션 토큰은 브라우저 메모리에만 두고 짧은 수명을 가지며 계정 자격 증명으로 사용하지 않는다. 초기 버전은 DB에 사용자 계정을 만들지 않는다.
- 닉네임은 본인 화면과 관측자 핀 상세에 공개된다. 입력 전에 이 사실과 관측 위치가 근사 위치로 공유된다는 점을 짧게 안내한다.

공개 서비스 전에는 닉네임 신고·차단 또는 금칙어 정책을 결정해야 한다. 화면에서는 닉네임을 항상 텍스트로 렌더링하고 HTML로 해석하지 않는다.

## 3. 관측 중 상태

사용자가 다음 조건을 모두 만족할 때만 `watching` 상태를 시작한다.

1. 유효한 방문 세션이 있다.
2. 지도 클릭으로 정한 관측 위치가 현재 밤 진입 기준을 만족한다.
3. 밤하늘 라우트에 진입해 화면이 활성 상태다.

밤하늘에서 지도로 돌아가거나, 밤 조건을 벗어나거나, 오류로 관측이 종료되면 즉시 상태를 종료한다. 탭이 숨겨지거나 연결이 끊기면 heartbeat가 멈추며 60초 안에 서버에서 만료한다. 복귀할 때 현재 밤 조건을 다시 통과한 경우에만 재등록한다.

초기 제안은 WebSocket 연결 후 20초 heartbeat, 서버의 60초 TTL이다. 연결 직후 전체 스냅샷을 받고 이후 추가·변경·삭제 이벤트를 받는다. 재연결 중에는 마지막 핀을 실시간 정보처럼 계속 두지 않고 `관측자 정보 연결 중` 상태를 표시한다.

## 4. 지도 핀과 위치 보호

정확한 클릭 좌표를 다른 사용자에게 그대로 보내지 않는다. 프론트엔드는 기본 0.25° 격자의 셀 중심으로 관측 위치를 변환해 presence API에 전달하고 서버도 같은 격자로 다시 정규화한다. 대략 수십 km 범위의 위치만 공유하며, 서버 응답에도 원본 클릭 좌표를 포함하지 않는다. 격자 크기는 환경 변수 `PRESENCE_CELL_SIZE_DEG=0.25`로 바꿀 수 있게 하고 `0 < 값 <= 10` 범위만 허용한다.

- 한 셀에 한 명이면 일반 관측자 핀, 여러 명이면 인원수가 적힌 집계 핀을 표시한다.
- 핀을 선택하면 해당 셀의 닉네임을 표시하되 인원이 많으면 일부와 `외 N명`으로 줄인다.
- 본인의 선택 마커, 다른 관측자 핀, 집계 핀은 모양과 접근성 이름을 구분한다.
- 핀과 집계 숫자는 밤 음영 위에서도 읽혀야 하며 지도 pan·zoom에 지리적으로 고정된다.
- 관측자가 0명이면 빈 지도를 정상 상태로 보여준다. WebSocket 장애는 지도 탐색과 밤하늘 감상을 막지 않는다.

이 근사 위치는 보조적인 보호 장치다. 사용자가 특정 장소를 의도적으로 선택할 수 있으므로 닉네임 입력 시 공개 범위를 고지한다. 지도 공급자나 검색 공급자가 받는 좌표와 presence 공개 데이터도 구분한다.

## 5. 서버와 데이터 수명

실시간 관측자 상태에는 여러 브라우저가 공유하는 서버가 필요하므로 Python + FastAPI 백엔드를 필수 구성으로 앞당긴다. 초기 구현은 프로세스 메모리의 TTL 저장소를 사용하며 서버 재시작 시 세션과 핀이 모두 사라진다. 계정·관측 이력·마지막 위치는 DB에 영구 저장하지 않는다.

단일 서버 프로세스에서 먼저 동작을 검증한다. 여러 인스턴스로 확장할 때는 Redis 같은 공유 presence 저장소와 pub/sub을 별도 어댑터로 추가한다. 프로세스 메모리 상태를 여러 서버 전체의 상태로 오해하지 않는다.

서버는 닉네임 길이와 문자, 위치 셀 범위, 메시지 크기, heartbeat 빈도를 검사한다. 세션 생성·재연결·상태 갱신에는 IP와 세션 단위의 제한을 두고, 클라이언트가 보낸 시각 대신 서버 UTC를 만료 기준으로 사용한다.

## 6. 밤 기준 환경 설정

밤 진입 경계의 기본값은 사용자가 정한 `-18°`다. 코드에 숫자를 반복해 넣지 않고 백엔드 환경 변수 `NIGHT_ALTITUDE_THRESHOLD_DEG=-18`에서 읽는다.

- 허용 범위는 `-90 <= 값 <= 0`이며 숫자가 아니거나 범위를 벗어나면 서버 시작을 실패시킨다.
- 공개 설정 API는 `nightAltitudeThresholdDeg`를 반환한다. 프론트엔드는 이 값을 밤 판정, 지도 음영 경계, 선택 카드, 관측 종료에 함께 사용한다.
- 프론트엔드는 별도의 `VITE_NIGHT_...` 값을 두지 않는다. 한 배포에서 서로 다른 기준이 생기는 것을 막는다.
- 설정 API를 불러오지 못하면 관측 진입은 차단하고 재시도를 제공한다. 지도 탐색과 검색은 계속 사용할 수 있다.
- 환경 변수 변경은 서버 재시작 후 적용한다. 열린 탭은 설정을 다시 받은 뒤 현재 위치를 재판정한다.

기본값을 바꾸더라도 시민·항해·천문박명의 과학적 경계 자체는 바뀌지 않는다. UI의 `관측 가능` 영역과 동일 밤 상태색의 경계만 배포 설정값을 따른다.

## 7. 후속 소셜 로그인과 채팅

소셜 로그인은 방문 세션을 대체할 수 있는 후속 기능이다. 현재 닉네임 세션과 presence 계약에서 내부 `participantId`와 공개 `displayName`을 분리해, 나중에 OAuth 계정 식별자를 연결해도 지도·하늘 화면을 크게 바꾸지 않도록 한다.

채팅은 이번 구현 범위에 포함하지 않는다. 같은 지역의 기준을 국가·도시·행정구역·좌표 격자 중 무엇으로 할지, 경계 지역과 바다를 어떻게 처리할지 먼저 결정해야 한다. 다음 항목을 정한 뒤 별도 기획과 API로 추가한다.

- 채팅방을 만드는 지역 단위와 이동 시 입·퇴장 규칙
- 로그인 필요 여부와 닉네임 사칭 대응
- 신고·차단·금칙어·도배 제한과 운영 책임
- 메시지 보관 기간, 삭제, 개인정보 안내
- 정확한 관측 좌표를 노출하지 않는 방 구조

초기 presence 격자를 향후 채팅방 기준으로 자동 확정하지 않는다. 채팅 범위를 정할 때 사용자 경험과 운영 정책을 다시 검토한다.

## 8. 완료 기준

- 닉네임을 정하지 않으면 지도에 진입할 수 없고 새로고침 시 같은 탭에서 유지된다.
- 두 브라우저가 서로 다른 밤하늘을 열면 메인 지도에 근사 관측 위치 핀이 나타난다.
- 같은 셀의 관측자는 한 핀으로 집계되고 상세에서 닉네임을 확인할 수 있다.
- 지도 복귀·밤 종료·연결 단절 후 60초 안에 해당 관측자가 사라진다.
- 정확한 클릭 좌표·계정·관측 이력이 presence 응답이나 영구 저장소에 남지 않는다.
- presence 장애가 지도 선택과 Stellarium 감상을 중단시키지 않는다.
- 밤 기준을 환경 변수로 바꾸면 코드 수정 없이 지도 경계와 진입 판정에 같은 값이 적용된다.
