# 개발 구조

Real Time Sky는 세계지도에서 현재 위치·시간의 태양 고도를 계산하고 하늘을 렌더링하며, FastAPI가 공개 설정을 제공하는 구조입니다.

## 사용자 흐름

1. 사용자는 웹페이지에 들어오면 바로 세계지도 화면을 봅니다.
2. 세계지도를 이동하거나 검색 결과로 원하는 지역을 찾습니다.
3. 지도 클릭으로 관측 위치 좌표를 확정합니다.
4. 해당 좌표가 태양 고도 기준을 만족하면 밤하늘 페이지로 들어갑니다.
5. 밤하늘 페이지에서는 현재 시각 기준의 하늘을 계속 렌더링합니다.
6. 선택 위치가 없거나 밤 조건을 만족하지 않으면 세계지도에 남습니다.

검색 결과는 지도 중심과 줌만 바꿉니다. 실제 관측 좌표는 지도 클릭으로만 확정됩니다.

## 저장소

```text
star/
├── backend/     # FastAPI 설정 API와 보류 중인 세션·presence API
├── docs/        # 공개 개발 문서
└── frontend/    # React 지도·하늘 UI와 Stellarium 연동
```

개인 개발 계획과 작업 메모는 `docs/private/`에 두며 Git에는 올리지 않습니다.

## 프론트엔드

`frontend/src/features`는 기능별 코드를 보관합니다.

- `night-eligibility`: 좌표와 현재 UTC의 태양 고도를 계산하는 순수 함수
- `map-explorer`: Leaflet 기반 태평양 중심 세계지도, OpenStreetMap 타일, 이동·확대·클릭 좌표 선택
- `map-lighting`: 지도 전체의 낮·박명·밤 상태 계산
- `place-search`: 로컬 도시 데이터 기반 장소 검색
- `sky-engine`: Stellarium Web Engine 어댑터와 하늘 시선 제어
- `visitor-session`, `presence`: 닉네임·관측자 표시 기능 재개를 위해 남아 있지만 현재 화면 흐름에서는 사용하지 않음

지도 음영은 외부 API 없이 2도 격자의 태양 고도를 계산합니다. 밤인 지역은 같은 색으로 표시하고, 박명 구간은 별도 안내 색으로 표현합니다. 지도 화면은 입장 시점의 시간을 기준으로 표시하며, 위치 클릭과 하늘 진입 판정은 현재 시간으로 다시 계산합니다. 메인 지도는 사이드 패널 없이 화면 대부분을 채우고, 상단 배너에서 팁·장소 검색·한국어/영어 표시 전환을 제공합니다.

Stellarium 제품 적용 전 실험 코드는 `frontend/experiments/stellarium`에 분리되어 있습니다. 제품 코드에서는 직접 API를 흩뿌리지 않고 하늘 렌더링 어댑터에서 JS/WASM 로딩과 자산 경로를 관리합니다.

## 백엔드

FastAPI는 현재 다음 공개 설정을 제공합니다.

| 경로 | 역할 |
| --- | --- |
| `GET /health` | 동작 환경 상태 확인 |
| `GET /config/public` | 밤 기준과 향후 presence 클라이언트 설정 제공 |

다음 API는 닉네임·관측자 표시 기능을 보류하면서 서버에는 남아 있지만 현재 프론트 화면에서는 호출하지 않습니다.

| 경로 | 역할 |
| --- | --- |
| `POST /sessions/visitors` | 검증된 닉네임의 임시 방문 세션 발급 |
| `WS /presence/ws` | 활성 관측자의 근사 위치 스냅샷 공유 |

## 환경 변수와 설정

`NIGHT_ALTITUDE_THRESHOLD_DEG`는 백엔드가 검증한 뒤 공개 설정으로 프론트엔드에 전달합니다. 이에 따라 지도 선택과 하늘 진입이 서버 설정과 같은 값을 사용합니다.

presence 관련 환경 변수는 현재 화면에서는 사용하지 않지만, 나중에 관측자 핀이나 채팅 기능을 되살릴 때 같은 설정 구조를 재사용할 수 있습니다.

## MVP 검증 기준

- 프론트엔드 타입 검사, 린트, 포맷 검사, 전체 테스트, production 빌드가 통과해야 합니다.
- 백엔드 포맷 검사, 린트, 타입 검사, 전체 테스트가 통과해야 합니다.
- 로컬 서버에서 `GET /health`, `GET /config/public`이 정상 응답해야 합니다.
- Vite 개발 서버에서 Stellarium JS/WASM 자산이 정상 제공되어야 합니다.

## 현재 제약

- 지도는 OpenStreetMap 공개 타일을 사용하므로 로컬 실행 환경의 인터넷 연결과 타일 서버 정책의 영향을 받습니다. 검색은 로컬 장소 데이터만 사용합니다.
- Stellarium 엔진은 통합되었지만 실제 다양한 화면에서 성능과 위치 동기화, 실시간 갱신 안정성은 계속 확인이 필요합니다.
- 닉네임, 소셜 로그인, 관측자 핀, 채팅, 실제 기상 반영은 아직 제공하지 않습니다.
