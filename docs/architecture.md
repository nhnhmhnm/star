# 서비스 구조

Real Time Sky는 브라우저가 현재 위치·시각의 태양 고도를 판정하고 하늘을 렌더링하며, FastAPI가 공통 정책과 짧게 유지되는 사용자 상태를 관리하는 구조입니다.

## 사용자 흐름

1. 닉네임을 입력해 임시 방문 세션을 만듭니다.
2. 세계지도를 이동하거나 검색 결과로 원하는 지역을 찾습니다.
3. 지도 클릭으로 최종 관측 좌표를 확정합니다.
4. 공개 설정의 태양 고도 기준을 충족할 때만 하늘 페이지를 엽니다.
5. 하늘 페이지가 열린 동안 근사 관측 위치를 WebSocket으로 공유합니다.
6. 지도로 돌아가거나 연결이 끝나면 관측 상태를 제거합니다.

검색 결과는 지도 중심과 배율만 바꿉니다. 관측 좌표는 지도 클릭으로만 확정됩니다. 선택 위치가 없는 `/sky` 접근은 세계지도로 돌아갑니다.

## 저장소

```text
star/
├── backend/     # FastAPI 설정·방문 세션·presence
├── docs/        # 공개 서비스 구조 문서
└── frontend/    # React 지도·하늘 UI와 Stellarium 실험
```

개인 구현 계획과 작업 메모는 `docs/private/`에 두며 Git에서 추적하지 않습니다.

## 프론트엔드

`frontend/src/features`는 기능별 코드를 소유합니다.

- `night-eligibility`: 좌표와 현재 UTC로 태양 고도를 계산하는 순수 함수
- `map-explorer`: Leaflet 기반 세계지도, OpenStreetMap 타일, 이동·확대·클릭 좌표 선택
- `map-lighting`: 지도 전체의 낮·박명·밤 상태 계산
- `place-search`: 공급자 계약과 현재의 로컬 도시 검색 구현
- `visitor-session`: 닉네임 검증과 탭 단위 세션 저장
- `presence`: 관측 상태 WebSocket과 근사 위치 핀

지도 음영은 외부 API 없이 10° 격자의 태양 고도를 계산합니다. 설정된 밤 기준 이하의 셀은 모두 같은 상태색을 사용합니다. 현재 구현은 세계지도에 들어온 시각의 스냅샷을 유지하며, 위치 클릭과 하늘 진입은 그 순간의 현재 시각으로 다시 판정합니다.

Stellarium 제품 연결 전 실험은 `frontend/experiments/stellarium`에 분리되어 있습니다. 제품 코드에서는 엔진 API를 직접 퍼뜨리지 않고 하늘 기능 경계의 어댑터에서 JS/WASM 수명주기와 자산 오류를 관리합니다.

## 백엔드

FastAPI는 다음 경계를 제공합니다.

| 경로 | 역할 |
| --- | --- |
| `GET /health` | 앱과 환경 상태 확인 |
| `GET /config/public` | 밤 경계와 presence 클라이언트 설정 제공 |
| `POST /sessions/visitors` | 검증된 닉네임의 임시 방문 세션 발급 |
| `WS /presence/ws` | 활성 관측자의 근사 위치 스냅샷 공유 |

라우터는 HTTP·WebSocket 입력을 검증하고 서비스에 전달합니다. 서비스는 시계와 메모리 저장소를 주입받아 세션 만료, 위치 격자화, heartbeat, TTL을 처리합니다. 저장소는 단일 프로세스용이며 여러 서버 인스턴스를 위한 공유 상태를 제공하지 않습니다.

## 설정과 개인정보

`NIGHT_ALTITUDE_THRESHOLD_DEG`, `PRESENCE_CELL_SIZE_DEG`, `PRESENCE_HEARTBEAT_SECONDS`는 백엔드가 검증한 뒤 공개 설정으로 프론트엔드에 전달합니다. 이에 따라 지도 선택, 하늘 진입, 클라이언트 격자화와 heartbeat가 서버 설정과 같은 값을 사용합니다.

서버는 임시 participant ID와 닉네임, 격자 중심, 마지막 heartbeat 시각만 메모리에 보관합니다. 정확한 클릭 좌표와 관측 이력, 계정 정보는 저장하지 않습니다. 닉네임은 인증 수단이 아니며 중복을 허용합니다.

## MVP 점검 기준

- 프론트엔드 타입 검사, 린트, 포맷 검사, 전체 테스트, production 빌드가 통과해야 합니다.
- 백엔드 포맷 검사, 린트, 타입 검사, 전체 테스트가 통과해야 합니다.
- 로컬 서버에서 `GET /health`, `GET /config/public`, `POST /sessions/visitors`가 정상 응답해야 합니다.
- Vite 개발 서버에서 Stellarium JS/WASM 자산이 정상 서빙되어야 합니다.

## 현재 제한

- 지도는 OpenStreetMap 공개 타일을 사용하므로 로컬 실행 환경의 인터넷 연결과 타일 서버 정책의 영향을 받습니다. 검색은 로컬 도시 목록으로 동작합니다.
- Stellarium 렌더러는 연결되었지만 실제 브라우저 화면에서의 모바일 터치 조작과 장시간 관측 안정성은 별도 실기기 확인이 필요합니다.
- 세션과 관측 상태는 서버 재시작 시 사라집니다.
- 소셜 로그인, 채팅, 실제 기상과 구름 표현은 구현되어 있지 않습니다.
