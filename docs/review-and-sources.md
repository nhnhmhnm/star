# 최신 기획 검토 결과와 공식 근거

검토일: 2026-09-07. 사용자의 후속 의견을 반영한 최신 기준이다. 현재는 문서 조사·수정만 진행하며 코드·패키지 설치·앱 실행·배포는 하지 않는다.

## 1. 확정된 방향

- 태양 중심의 기하 고도 **-18° 이하**인 천문학적 밤만 하늘 진입 가능
- 배속·일시정지·임의 날짜·시간 이동 없이 현재 시각만 사용
- 지도 줌·드래그·스와이프·장소 검색으로 탐색하고 최종 클릭/tap으로 좌표 확정
- 검색 결과는 지도 이동·확대만 수행
- 낮 중심부는 손전등처럼 부드럽고 넓게 밝고, 관측 가능한 h <= -18° 영역은 동일한 밤 색상·투명도의 읽기 쉬운 지도
- 하늘은 대기를 켠 천문 렌더링으로, 균일한 검정 배경을 강제하지 않음
- 기상 데이터 기반 구름과 상태 안내는 추가 검토안으로 정리

이전 문서의 낮 진입 허용·배속·직접 좌표 입력안은 사용자 의도에 맞춰 제거했다. 전체 문서의 요구사항·상태·UI·향후 검증도 같은 기준으로 변경했다.

## 2. 세계지도는 원하는 방식으로 가능한가?

가능하다. Google Maps 공식 자료는 지도 줌·pan, 장소 검색 결과로 이동·확대, 지도 클릭에서 좌표 수신을 각각 설명한다. 우리 기획에서는 검색 결과를 즉시 관측자로 적용하지 않고 마지막 클릭을 추가한다. [지도 조작](https://developers.google.com/maps/documentation/javascript/interaction), [검색](https://developers.google.com/maps/documentation/javascript/place-autocomplete-new), [클릭 좌표](https://developers.google.com/maps/documentation/javascript/examples/event-click-latlng)

Google Maps 같은 UX는 확정했지만 실제 Google API 계약은 확정하지 않았다. 공급자 선정에서는 지도와 검색을 함께 비교하고 한국어 검색·지역 범위·비용·표시 조건을 확인한다.

## 3. 지도 낮/밤 밝기는 어떻게 표현하나?

현재 태양 고도로 계산한 연속 밝기장을 지도 지리 좌표에 붙인다. 낮 중심부는 밝고 아침·저녁·박명을 거쳐 밤으로 부드럽게 어두워지는 기획이다. 한국이 정오 부근이면 한국을 포함한 낮 영역이 넓게 밝게 보이게 한다.

빛 중심을 임의 도시나 화면에 고정하지 않는다. 시계의 정오와 태양이 가장 높은 시각은 꼭 같지 않으며 계절·위도·지도 투영도 모양에 영향을 준다. 따라서 ‘손전등 느낌’은 넓고 부드러운 밝기 효과로 구현할 계획이며 지구 위의 낮 영역을 화면의 완벽한 원으로 고정하지 않는다.

사용자가 추가로 정한 기준에 따라 h <= -18° 영역은 모두 동일한 밤 상태색·투명도를 적용한다. 이 범위 안에서는 더 깊은 밤이나 기상에 따른 추가 그라데이션을 넣지 않는다. 밤 음영은 지명·도로를 읽을 수 있도록 상한을 두고 선택 마커·버튼은 그 위에 표시한다. 관측 가능 여부는 -18° 경계와 카드 텍스트로 별도 안내한다. 밝은 지도와 실제 하늘의 밝기를 같은 색으로 맞추는 기능은 아니다.

## 4. 밤하늘 배경은 항상 같은 검정인가?

**아니다.** Stellarium Web Engine은 대기 표현을 지원하며 확인한 대기 소스는 태양·달 위치와 밝기, 탁도·광공해 설정 등을 계산에 사용한다. 같은 검은 사진을 배경으로 고정하는 구조가 아니다. [공식 대기 소스](https://github.com/Stellarium/stellarium-web-engine/blob/master/src/modules/atmosphere.c)

이번 서비스는 -18° 이하만 열기 때문에 태양의 박명 영향이 큰 밝은 하늘은 대부분 진입 범위 밖이다. 다만 달과 대기 표현, 보는 방향 등에 따른 밝기 차이는 남을 수 있으므로 밤 배경을 동일 RGB로 강제하지 않는다. 실제 출력 차이는 선택한 엔진 버전·설정으로 향후 검증한다.

기본 광공해 설정이 실제 도시의 광공해 데이터와 자동 연결되는 것은 아니다. 구름도 단순히 검은 막이 되는 것으로 정하지 않는다. 달빛이나 지상광에 비친 구름의 밝기를 정확히 재현하려면 추가 모델이 필요하다.

## 5. 구름·기상 상황을 고려할 수 있나?

가능하다. 위치별 운량·날씨 코드·강수 등 기상 데이터를 조회하고 그에 맞는 안내와 구름 표현을 추가할 수 있다. Open-Meteo의 현재 기상은 모델 기반 값이며 현장 구름의 실제 모양·픽셀 위치를 알려주는 API는 아니다. [공식 기상 문서](https://open-meteo.com/en/docs)

추천 범위는 기상 요약·자료 기준 시각을 먼저 제공하고, 운량 기반 구름·가림은 합성 품질과 성능 검증 후 추가하는 것이다. 맑음에도 항상 구름을 넣기보다 운량을 따르고, 실패는 맑음이 아니라 기상 미반영으로 표시한다. 상세 갱신·누락·표현 규약은 [기상 반영 검토안](./weather-integration.md)에 정리했다.

## 6. 현재 시간만으로도 별이 움직이나?

현재 UTC를 계속 반영하고 지평선 기준 시선을 고정하면 일주운동이 나타난다. 엔진의 시간·시선 처리 소스가 이를 뒷받침한다. [시간·시선 소스](https://github.com/Stellarium/stellarium-web-engine/blob/master/src/navigation.c)

몇 초만 보면 거의 멈춰 보일 만큼 느릴 수 있다. 이를 배속으로 바꾸지 않고 현재 시각과 자연스러운 이동으로 표현한다. 천문 시각은 계속 흐르며 기상은 별도 주기로 갱신한다.

## 7. 확대·별자리 기능

코어의 FOV 제어와 별자리 모듈의 선·이름 표시를 활용한다. 별·sky culture 데이터를 등록해야 하며 연결선을 직접 새로 만들 필요는 없다. 한글 툴팁·선 위 선택·그림·경계는 별도 범위다. [코어](https://github.com/Stellarium/stellarium-web-engine/blob/master/src/core.c), [별자리](https://github.com/Stellarium/stellarium-web-engine/blob/master/src/modules/constellations.c), [데이터 등록 예제](https://github.com/Stellarium/stellarium-web-engine/blob/master/apps/simple-html/stellarium-web-engine.html)

## 8. 검증·남은 결정

밤 경계는 사용자 결정이며, 천문학적 박명 정의는 [USNO](https://aa.usno.navy.mil/faq/RST_defs)를 참고한다. SunCalc 버전별 고도 단위·기하/겉보기 규약은 [1.9.0](https://github.com/mourner/suncalc/tree/v1.9.0)과 [현재 문서](https://github.com/mourner/suncalc)를 구분한다.

현재 공식 소스 확인과 실제 프로젝트의 동작 검증은 다르다. 엔진 커밋·자산·지도 공급자·기상 채택 범위·실기기 성능·라이선스 대응은 [결정·위험 관리](./decisions-and-risks.md)와 [향후 구현 계획](./implementation-plan.md)에 남겼다. 변경 가능한 master 근거는 개발 시 사용할 커밋으로 고정한다.
